# 统一每日总结验收

## 接口

MCP 仍为 `health` 工具，使用 `action: daily_summary`。支持 `date`（缺省今天），或完整 `start_date` / `end_date`（含两端，最多31天），不接受混合日期参数或小时裁切。原四个 summary action 从公开枚举删除并拒绝调用；四个 detail 和运动查询保留。内部睡眠 summary 用于复用既有归档逻辑，不是公开 MCP 入口。

每日包含睡眠、心率、血氧、压力；三指标统计有效去重点数、最小/最大/平均值，空指标为0点且统计值不可用。今天仅统计截至当前的点，未完成及未来小时不参与小时比较。

相对低采样：至少两个有有效点的完整小时，以其点数中位数为基准，严格少于一半标为“数据较少时段”，并非只有0点才标。实际点数及同期心率点数均展示。连续偏少小时且同期心率有无分支一致时合并并累加点数；心率分支改变则断开，避免混淆提示。同期有心率提示“可能处于省电模式中或手部动作较大”，同期0心率提示“可能未佩戴或佩戴不紧”；列其他可能原因并明确不能确定。整天0点或不足比较不推断原因。时段使用带UTC偏移的当地时间，回拨重复小时可区分。

## 真机

`DailySummaryProbe` 使用应用自身配置在内存读取鉴权，调用手机实际 `127.0.0.1:17891/mcp`；不导出Token、原始健康数据，不触发消息发送。验证列表、单日、两日范围、四个旧概括拒绝、四个详细入口可用。首次探针因Instrumentation重启目标进程而使原服务监听消失，改为在探针线程中启动原前台服务并有界等待监听，复验PASS。验收后恢复正常后台服务。

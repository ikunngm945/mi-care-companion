# 天气原生云端刷新验收（2026-11-14）

## 已确认需求

手机当地每日00:00、02:00…22:00请求云端并更新助手缓存供MCP查询；不是向用户发天气消息，也不是每次MCP查询联网。启动/重启仅注册下一个时刻，不补发关机期间所有时刻。夏令时跳过不存在的当地时刻，重复时刻取较早一次。

## 实现边界

- 当前已安装小米天气17.0.3.28（17000328）。模块仅在原生进程内部调用`B1.k.f(Context,CityData)`，复用原生鉴权、联网同意校验及首页城市；不提取/保存账户或token。原生网络连接及读取超时各5秒，整体执行仍以原生实现为准。
- `Z1.j1.m`持久化后比较原生返回的更新时间与首页城市`raw.insert_time`，然后发送既有白名单投影。主程序再次确认助手收到的`cache_updated_at_epoch_ms >= 本轮开始时间`才记录成功。
- 原生HTTP在独立单线程运行，socket立即返回pending，不重入、不假取消。丢失回复后仅轮询状态，不盲目重新开始网络任务。
- 使用AlarmManager RTC_WAKEUP；已有精确权限时exact-and-idle，否则降级为系统可延迟调度并在界面提示。时区/时间变化重排。100秒上限partial唤醒锁保CPU；前台主服务持有稳定天气Provider引用直到本轮结束，避免天气进程作为cached被回收，不打开天气界面。
- 周期采集与云端采集/发送共用锁，避免旧快照晚于新快照覆盖。MCP区分观测时间、云端完成时间与失败缓存，不伪造实时成功。
